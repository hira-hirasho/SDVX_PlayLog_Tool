# SDVX PlayLog Tool UI仕様書

## 1. 文書情報

- 文書名：SDVX PlayLog Tool UI仕様書
- バージョン：1.0
- 最終更新：2026-09-21
- 対象OS：Windows 11
- 対象アプリ：SDVX PlayLog Tool
- UI実装：React / TypeScript
- UI実行環境：Electron 44.4.1
- UIビルド環境：Vite 8.3.0
- データソース：SQLite

本仕様書は、SDVX PlayLog ToolのUIについて、利用者から見える画面構成、表示内容、操作方法、検索、ページング、プレイ詳細、メディア表示、およびUIの動作仕様を定義する。

本仕様書では、UIの具体的な内部実装方法は定義しない。

SDVXプロセス監視、リザルト検出、OCR、プレイ記録生成、Replay処理、メディア生成等のバックエンド処理も本仕様書の対象外とする。

---

# 2. UIの役割

UIは、保存済みのプレイ履歴を閲覧・検索し、プレイに紐づくメディアを確認するためのデスクトップアプリケーションである。

基本的な利用フローは以下とする。

```text
プレイ履歴一覧
↓
検索・ページング
↓
プレイ選択
↓
プレイ詳細
├─ プレイ情報
├─ パフォーマンス
├─ GRADE
└─ メディア
    ├─ RESULT IMAGE
    └─ REPLAY VIDEO
```

UIはプレイ記録の生成、SDVXの監視、OBSの制御、OCR、Replay処理等を行うものではない。

---

# 3. UIの基本方針

以下をUIの基本方針とする。

1. プレイ履歴は保存済みのSQLiteデータを表示する。
2. プレイは`play_id`によって識別する。
3. ExcelをUIのデータソースとして使用しない。
4. プレイレコードからメディアの保存場所を特定する際は`play_id`を基準とする。
5. `result.png`と`replay.mp4`は、それぞれ独立して表示する。
6. プレイレコードとメディアは独立して扱う。
7. UIはPythonバックエンドとは独立したアプリケーションとして動作する。
8. UIとPythonバックエンドは、直接的なアプリケーション間通信によってプレイデータを受け渡さない。
9. UIを終了してもPythonバックエンドを終了させない。
10. Pythonバックエンドの状態によって、UIの画面状態を直接切り替えない。
11. 装飾やアニメーションは、情報の可読性および操作性を損なわない範囲で使用する。

---

# 4. UIとバックエンドの関係

UIとPythonバックエンドは独立して動作する。

両者は、保存済みのSQLiteデータおよびメディアを介して同一のプレイ履歴を参照する。

```text
Python Backend
    │
    ├──→ SQLite
    │
    └──→ Media
             │
             ↓
        Electron UI
```

UIはPythonバックエンドの実行状態を制御しない。

UIから以下の処理を実行しない。

```text
Python Backend起動
Python Backend終了
SDVX起動
OBS起動
SDVX監視開始
```

PythonバックエンドからUIを起動・終了・制御しない。

UIの状態とPythonバックエンドの`ACTIVE` / `SLEEP`状態は、それぞれ独立した概念として扱う。

# 5. UIが利用する保存データ

## 5.1 ランタイムデータ

UIが利用するランタイムデータの基準ディレクトリは以下とする。

```text
%LOCALAPPDATA%\SDVX PlayLog Tool\data
```

UIが利用する主要なデータは以下とする。

```text
data/database/playlog.db
data/media/<play_id>/result.png
data/media/<play_id>/replay.mp4
```

実際の保存場所は以下となる。

```text
%LOCALAPPDATA%\SDVX PlayLog Tool\data\database\playlog.db

%LOCALAPPDATA%\SDVX PlayLog Tool\data\media\<play_id>\result.png

%LOCALAPPDATA%\SDVX PlayLog Tool\data\media\<play_id>\replay.mp4
```

`logs`および`temp`は、UIの通常表示対象としない。

---

## 5.2 プレイ識別

プレイの識別には`play_id`を使用する。

```text
play_id = UUIDv7
```

以下をプレイ識別子として使用しない。

```text
日時
曲名
アーティスト名
Excel行番号
SQLite上の行番号
```

一覧から詳細画面への遷移、および詳細画面での対象プレイの特定には`play_id`を使用する。

---

## 5.3 メディア保存構造

プレイに紐づくメディアは、プレイ単位のディレクトリに保存される。

```text
data/media/<play_id>/
├─ result.png
└─ replay.mp4
```

メディアの存在はプレイレコードとは独立して判定する。

---

# 9. GRADE表示

GRADEはSCOREを基準としてUI上で算出・表示する。

使用するGRADEは以下とする。

```text
D
C
B
A
A+
AA
AA+
AAA
AAA+
S
```

判定基準：

```text
9,900,000以上 → S
9,800,000以上 → AAA+
9,700,000以上 → AAA
9,500,000以上 → AA+
9,300,000以上 → AA
9,000,000以上 → A+
8,700,000以上 → A
7,500,000以上 → B
6,500,000以上 → C
6,500,000未満 → D
```

GRADEはUI上の表示情報であり、プレイレコードの保存条件とは別の概念とする。

GRADEごとに専用の表示表現を使用する。

# 16. メディア表示

詳細画面には、プレイに紐づくメディアを表示する領域を設ける。

セクション名：

```text
MEDIA STREAM
```

```text

```

```text

```

---

## 16.1 RESULT IMAGE

`result.png`が存在する場合、保存済みのリザルト画像を表示する。

```text
data/media/<play_id>/result.png
```

画像をクリックすると拡大プレビューを表示する。

---

## 16.2 REPLAY VIDEO

`replay.mp4`が存在する場合、保存済みのReplay動画を表示する。

```text
data/media/<play_id>/replay.mp4
```

動画は標準的な動画操作を利用できる。

利用者は再生、一時停止、シーク等の動画操作を行える。

---

## 16.3 メディアの独立性

画像と動画は独立して存在判定・表示する。

想定される状態：

```text
result.pngあり / replay.mp4あり
result.pngあり / replay.mp4なし
result.pngなし / replay.mp4あり
result.pngなし / replay.mp4なし
```

### 両方存在する場合

RESULT IMAGEとREPLAY VIDEOを並べて表示する。

```text
┌─────────────────────┬─────────────────────┐
│ RESULT IMAGE        │ REPLAY VIDEO        │
│                     │                     │
└─────────────────────┴─────────────────────┘
```

### result.pngのみ存在する場合

RESULT IMAGEのみを表示する。

Replay VIDEO領域は表示しない。

### replay.mp4のみ存在する場合

REPLAY VIDEOを表示する。

RESULT IMAGEが存在しないことを示すプレースホルダーを表示する。

### どちらも存在しない場合

プレイ情報は通常どおり表示する。

メディア領域には、メディアが存在しないことを示す表示を行う。

---

# 17. メディアとプレイ履歴の独立性

SQLiteのプレイレコードとメディアファイルは独立して存在する。

```text
SQLiteあり
+
メディアあり
→ プレイ情報・メディアを表示

SQLiteあり
+
メディアなし
→ プレイ情報のみ表示
```

メディアのみが存在する場合、メディアからプレイ履歴を生成・推測しない。

```text
SQLiteなし
+
メディアあり
→ UI上のプレイ履歴として表示しない
```

# 19. UI状態

UIでは、利用者から見て以下の状態を区別する。

```text
Loading
Success
Empty
Error
```

## Loading

データ取得中は必要に応じてローディング表示を行う。

## Success

正常にデータを取得できた場合は通常の画面を表示する。

## Empty

以下はエラーではなく空状態として扱う。

```text
プレイ履歴が0件
検索結果が0件
```

表示例：

```text
NO DATA

該当するプレイ履歴がありません
```

検索結果が0件の場合、不要なページング操作は表示しない。

## Error

データ取得等に失敗した場合は、利用者が状況を把握できる形でエラーを表示する。

既存データを推測・補完して表示しない。

---

# 20. 対象プレイが存在しない場合

詳細画面で指定された`play_id`に対応するプレイレコードが存在しない場合、通常のプレイ詳細を表示しない。

メディアが存在していたとしても、メディアからプレイレコードを推測・復元しない。

対象プレイが存在しないことを利用者が把握できる表示を行う。

---

# 21. メディアの外部変更

詳細画面表示後に、外部操作によってメディアファイルが削除・変更された場合、次回メディア取得時には最新のファイル状態を反映する。

UIは存在しないファイルを存在するものとして扱わない。

---

# 22. UIのデータ更新

UIはPythonバックエンドからのリアルタイム通知によってプレイ履歴を自動更新しない。

データを再取得する主な契機は以下とする。

```text
UI起動
一覧画面表示
ページ変更
検索条件変更
RESET
UI再読み込み
```

PythonバックエンドからUIへのリアルタイムPushによって一覧を更新する機能は提供しない。

---

# 23. UIライフサイクル

## 23.1 Backendのみ起動

正常な状態とする。

```text
Python Backend
↓
常駐
↓
UIなし
```

UIが起動していなくてもPythonバックエンドは動作できる。

---

## 23.2 UIのみ起動

Pythonバックエンドが停止していても、保存済みのSQLiteおよびメディアを利用できる限りUIを使用できる。

```text
Electron UI
↓
保存済みデータの読み取り
```

---

## 23.3 両方起動

以下を通常の利用状態とする。

```text
Python Backend
+
Electron UI
```

---

## 23.4 UI終了

UIを終了してもPythonバックエンドを終了させない。

```text
Electron UI終了
↓
Python Backend継続
```

---

## 23.5 Backend終了

Pythonバックエンドが終了してもUIを自動終了させない。

UIは保存済みデータを利用できる範囲で継続して使用できる。

```text
↓
ONLINE
```

データベース接続状態は以下のような表示を行う。

```text
LINKING
↓
CONNECTED
```

データ取得後にはレコード件数を表示する。

例：

```text
0001 RECORDS
```

## 25.2 Reduced Motion

OSの`prefers-reduced-motion`が有効な場合、UIアニメーションを抑制または停止する。

アニメーション停止時も情報表示および操作性を維持する。

# 26. Electron単一起動

UIは同時に複数インスタンスを起動しない。

2回目以降の起動では、既に起動しているUIを利用する。

既存UIが最小化されている場合は復元し、既存UIへフォーカスを移す。

動作イメージ：

```text
UI 1個目
↓
通常起動

UI 2個目
↓
2個目は新規UIを表示しない
↓
既存UIを復元
↓
既存UIへフォーカス
```

---

# 27. 起動・終了

PythonバックエンドはWindowsログオン時に自動起動する。

UIはWindowsログオン時に自動起動しない。

UIはユーザー操作によって起動する。

想定される起動手段：

```text
デスクトップショートカット
スタートメニュー
タスクバー
アプリケーション本体
```

UI起動によって以下を実行しない。

```text
Python Backend起動
SDVX起動
OBS起動
SDVX監視開始
```

# 28. UIパッケージング

UIはElectronアプリケーションとしてWindows向けにパッケージ化する。

基本的な構成は以下とする。

```text
React / TypeScript
↓
Vite
↓
Electron
↓
Windowsアプリケーション
```

アプリケーション本体とランタイムデータは分離する。

```text
Program / Install Directory
↓
Electronアプリ本体

%LOCALAPPDATA%\SDVX PlayLog Tool\data
↓
SQLite
Media
Logs
Temp
```

UIの利用に必要な保存データをアプリケーション本体のインストールディレクトリへ保存しない。

# 33. 外部仕様と内部実装の分離

本仕様書では、利用者から見えるUIの仕様を定義する。

以下のような具体的な実装方法は、本仕様書では規定しない。

```text
Reactコンポーネントの分割方法
React Hooksの構成
Stateの管理方法
Electron Main Processの具体的な実装
Renderer Processの具体的な実装
preloadの実装
RendererとMain間のAPI実装
window.apiの具体的な型
SQLiteライブラリおよびクエリの実装
メディアファイルの読み込み方法
Electronのプロトコル実装
Electronのセキュリティ設定
BrowserWindowの設定
Viteの設定
electron-builderの設定
CSSの実装方法
アニメーションの実装方法
```

これらはUI内部仕様として別途定義する。

外部仕様と内部仕様で同じ内容を重複して定義しない。

外部仕様に記載された動作を満たすことを前提として、内部仕様ではその実現方法を定義する。

# 34. UI仕様の基準

本仕様書におけるUIの基本的なデータフローは以下とする。

```text
SQLite
↓
プレイ履歴一覧
↓
play_id
↓
プレイ詳細
├─ プレイ情報
├─ SCORE / EX SCORE
├─ GRADE
└─ メディア
    ├─ result.png
    └─ replay.mp4
```

メディアはプレイレコードに保存されたメディアパスを利用するのではなく、`play_id`を基準として対象メディアを特定する。

```text
play_id
↓
data/media/<play_id>/
├─ result.png
└─ replay.mp4
```

UIはPythonバックエンドとは独立して動作する。

BackendからUIへのリアルタイムPushは行わない。

UIの現行必須機能は以下とする。

```text
プレイ履歴の閲覧
プレイ履歴の検索
ページング
プレイ詳細表示
GRADE表示
メディア表示
リザルト画像プレビュー
```

以下は将来機能として扱う。

```text
メディア削除
Windows Explorerによるフォルダ操作
X共有
プレイ履歴削除
```

以上を、現時点における「SDVX PlayLog Tool UI仕様書 v1.7」の基準とする。
